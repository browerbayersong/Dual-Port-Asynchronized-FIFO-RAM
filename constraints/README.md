# 目标器件确定后的约束意图

本目录保留最初约束意图，并新增已在TD V6.2.168116、PH1A100SFG676上执行的td_eval.sdc与独立端点审计td_endpoint_audit.tcl。它们针对analysis/dual_fifo_eval.v层次，不是任意工具通用SDC。16组最大延迟472条路径已核对；set_max_skew没有独立生效报告，不声称其独立签核。完整接口时序尚未收敛，详见 [目标分析](../docs/TARGET_ANALYSIS.md)。任务书未要求实物上板。

| 对象 | 必须实现的约束/检查 |
| --- | --- |
| 五个时钟 | a_wr_clk、a_rd_clk、b_wr_clk、b_rd_clk、monitor_clk 分别建立真实周期/波形；外部输入输出延迟按连接定义 |
| 指针跨域 | 源为寄存的 wgray/rgray；目的为对侧同步链首级，识别四条 9 位总线 |
| 同步链 | 使用目标工具识别的同步器属性，保留级数、约束同步级间正常时序，并检查放置及可靠性报告 |
| Gray 总线 | 按源时钟及物理实现要求设置最大数据路径延迟/位间偏斜，逐总线报告实际受约束路径 |
| 请求与确认 | 识别四个 mailbox 的单 bit 请求/确认同步链；异步例外不能掩盖级间时序 |
| 保持数据总线 | 源捕获保持至确认；按控制同步和 GUARD 等待窗口证明源到监控数据在捕获前稳定，约束/验证最长数据路径 |
| 复位 | 异步断言、各域两级同步释放，按工具规则分析恢复/移除和复位树 |
| RAM | 检查两路独立 RAM 的映射、双时钟端口和读输出寄存器归属 |

不能简单用全域 `set_clock_groups -asynchronous` 或宽泛 `set_false_path` 后便认为 Gray/bundled-data 已受最大延迟保护；部分工具的优先级会让最大延迟约束被忽略。需要报告例外、受约束起止点、未约束路径和时序覆盖情况。

RTL 给定的 20/12/35/10 ns 与监控 10 ns 只是仿真配置，不能自动当成课程最终目标器件的时序规格。器件确定后由项目明确接口和频率目标，再运行时序分析。
