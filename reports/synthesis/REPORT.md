# 通用综合报告

日期：2026-10-24。用户确认“未指定，先做通用综合”。顶层 `dual_async_fifo`，两路 256×32，COUNT_WIDTH=32，AUTO_REFRESH_CYCLES=32；仅 SYNC_STAGES 改变。

工具实测为 Yosys 0.70，Git `28ba3cb92`，通过 YoWASP 包 0.70.0.0.post1259 运行。没有器件库、Liberty、ABC、布局布线或时序分析。

硬件单元数排除了各 26 个 `$scopeinfo` 元数据单元。Yosys 原始 `stat` 报告保留这些元数据，因此原始总数分别为粗粒度 309/321、展开后 37408/37452；汇总 JSON 同时保存原始与校正口径。不同类型单元不能按个数等同为面积。

44 位增量包括四条 9 位指针同步链增加的 36 位，以及监控请求/确认同步增加的 8 位。复位同步链固定为两级，不随 SYNC_STAGES 改变。

第一阶段保存两块 `$mem_v2`，各 WIDTH=32、SIZE=256，说明两路独立存储被识别为抽象 RAM。不能据此声称已经映射到 FPGA 块 RAM。第二阶段故意将 RAM 展开为 FF/选择逻辑，供无器件条件下比较；它不是实际 FPGA 资源预测。抽象 RAM 内可吸收读端寄存器，优化也会合并常量等，因此不能将第一阶段外部寄存器简单加上 RAM 位数与第二阶段作等式比较。

两阶段均执行 `check -assert` 并通过；未推断锁存器。警告包括同步链数组 `pipe` 被换为寄存器（预期的同步寄存器实现），以及 Yosys 提醒 `translate_off` 是被支持的传统注释而非语言标准。后者用于将参数错误检查排除出综合；合法运行的保护逻辑不因此被移除。所有原始警告仍保留在日志内。
